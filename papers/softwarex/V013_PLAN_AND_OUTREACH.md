# ChromeRAG 0.1.3: SoftwareX plan and outreach (working document)

Status 2026-10-01. Nothing here has been published or pushed. Items marked **[approval]** change
something outside this checkout (GitHub, PyPI, Zenodo, other people's repositories) and wait for the author.

## 1. What changed that the paper must say

| Paper today (0.1.2) | 0.1.3 |
|---|---|
| Heuristic pipeline: landmark/class pruning, density, DVDF hashed vectors | Learned block filter (gradient-boosted trees, 150 KB, NumPy inference) after the same cleaning stages; DVDF is only the fallback (`enable_lbc=False`) |
| Anchor metric (blind to chrome inside `<main>`), 242 docs pages | Human-reviewed WCXB (1,495 dev pages, 7 page types), word F1 with/without snippets, cross-validated by site |
| ~75 ms/page | ~29 ms/page, faster than Trafilatura (~31 ms) |
| Wins on recall vs Trafilatura, ties on noise | Wins on F1 overall (+0.028 [+0.018, +0.038], balanced) and on forum, collection, listing, service; ties articles; documentation within noise |
| Output has link URLs, breadth-first order | No URLs by default, document order, repeats removed |

New title candidate: *ChromeRAG: a learned boilerplate filter and site-template learner for web RAG ingestion*.

## 2. Evidence still to produce (in order)

1. **Freeze** (author says so). Then once only: WCXB **test** (473 sites), landing **held-out**, **fresh companies**
   (`poc/landing_companies_fresh.json`). Final model = trained on all of dev, thresholds fixed (0.30/0.50/0.70).
2. Ablation on dev (all cheap, no API): heuristic only (`enable_lbc=False`) vs learned; feature groups
   (text, position, ancestor names, repeated structure, heading above); with/without exact-repeat removal;
   link targets on/off. Report as a table with CIs.
3. Precision-recall frontier: sweep the threshold per cross-validation fold and plot ChromeRAG's curve with
   Trafilatura/Readability/MarkItDown as points (Fig. 2 replacement).
4. Retrieval: BM25 (no API) on landing and benchmark corpora with the new output; dense retrieval
   (`text-embedding-3-small`, ~$0.1) and the blind pairwise judge (`gpt-5.6-luna`, ~$0.5 of the remaining
   ~$0.96) **after** freeze, run by the assistant, cap `$1.80`.
5. Human check: 40 pages, two outputs shown blind (ChromeRAG vs Trafilatura), author rates which is better
   for a RAG chunk. Report as a small agreement table (it is the only evidence not derived from the same
   labels the model was trained on).
6. Error analysis paragraph: where it loses (documentation short headings and code captions; comment
   threads on article pages; related-link lists) with two example pages each. Honest limitation list:
   JS shells, label ambiguity on product/collection/listing pages (ceiling 0.80-0.85), English-centric
   stop-word and CTA features, model trained on WCXB's page mix.
7. Speed table from `poc/bench_speed.py` (single process, 200 fixed pages) with Trafilatura, MarkItDown,
   Readability.

## 4. Review-risk checklist (what a SoftwareX reviewer will push on)

* "Is this just Trafilatura?" -> head-to-head on a human-reviewed benchmark with CIs, plus the page types where
  it wins, plus honest ties on articles.
* "Evaluation on training data?" -> only cross-validated (site-grouped) and untouched-test numbers appear.
* "Impact?" -> see Section 3; do not overclaim.
* "Reproducible?" -> `pip install chromerag`, README quick start tested in CI, `evaluations/` folder, golden
  tests, Docker.
* "Maintained?" -> CHANGELOG, CONTRIBUTING, SECURITY, issue templates [add], release tags, Zenodo.
* Word/page limits and the Elsevier template: run `scripts/check_softwarex_draft.py` before upload.
